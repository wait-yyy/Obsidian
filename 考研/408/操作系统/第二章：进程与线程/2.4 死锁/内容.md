## 2.4 死锁 — 思维导图

### 一、死锁的概念

#### 定义
- **死锁**：各进程因竞争资源而互相等待对方手里的资源，导致各进程都阻塞，无法向前推进
- 若无外力干涉，这些进程将无法向前推进

#### 死锁 vs 饥饿 vs 死循环

| 概念 | 区别 |
|------|------|
| **死锁** | ≥2个进程互相等待，都阻塞 |
| **饥饿** | 单个进程长期得不到想要的资源 |
| **死循环** | 单个进程跳不出某个循环（程序员的bug）|

---

### 二、死锁产生的四个必要条件

**缺一不可！**

| 条件 | 说明 |
|------|------|
| **互斥条件** | 资源只能一个进程使用 |
| **不剥夺条件** | 资源只能主动释放，不能强行夺走 |
| **请求和保持条件** | 已持有一个资源，又请求新资源，被阻塞时不释放已有资源 |
| **循环等待条件** | 存在进程资源的循环等待链 |

> ⚠️ 发生死锁时一定有循环等待，但循环等待未必死锁（必要不充分条件）

---

### 三、死锁的处理策略

#### 框架
```
预防死锁 ──→ 破坏四个必要条件之一
避免死锁 ──→ 银行家算法（防止进入不安全状态）
检测死锁 ──→ 资源分配图化简
解除死锁 ──→ 资源剥夺 / 撤销进程 / 进程回退
```

---

#### 1. 预防死锁（静态）

| 破坏条件 | 方法 | 缺点 |
|---------|------|------|
| **互斥** | SPOOLing 改造成共享设备 | 不是所有资源都能改造 |
| **不剥夺** | 请求失败就释放所有资源 / OS强行剥夺 | 实现复杂，可能饥饿 |
| **请求和保持** | 静态分配（一次申请完所有资源） | 资源利用率极低 |
| **循环等待** | 顺序资源分配（按编号递增请求） | 编程麻烦，资源浪费 |

#### 2. 避免死锁（动态）— 银行家算法

**核心思想**：资源分配前预判是否会导致系统进入**不安全状态**

**数据结构**：
- Available：可用资源数
- Max：各进程最大需求
- Allocation：已分配资源
- Need = Max - Allocation：还需要多少
- Request：进程此次申请的资源数

**算法步骤**：
1. Request ≤ Need？→ 否则出错
2. Request ≤ Available？→ 否则等待
3. **试分配** → **安全性检查**（找安全序列）
4. 安全→正式分配；不安全→阻塞等待

**安全状态**：能找出一个安全序列，所有进程都能顺利完成

#### 3. 检测死锁
- **资源分配图**化简
  - 能消除所有边 → 无死锁
  - 不可简化 → 发生死锁

#### 4. 解除死锁
| 方法 | 说明 |
|------|------|
| **资源剥夺法** | 挂起某些死锁进程，剥夺其资源 |
| **撤销进程法** | 强制撤销部分/全部死锁进程 |
| **进程回退法** | 让进程回退到足够避免死锁的状态 |
