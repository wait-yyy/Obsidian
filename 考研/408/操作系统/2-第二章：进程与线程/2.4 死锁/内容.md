## 2.4 死锁 — 思维导图

### 一、死锁的概念

#### 定义
- **死锁**：各进程因竞争资源而造成的一种状态，各进程互相等待对方手里的资源，若无外力干涉，这些进程都将无法向前推进
- 发生死锁后，所有死锁进程都处于阻塞态

#### 死锁 vs 饥饿 vs 死循环

| 概念 | 区别 |
|------|------|
| **死锁** | ≥2个进程互相等待，都阻塞（管理者OS的问题）|
| **饥饿** | 单个进程长期得不到想要的资源（管理者OS的问题）|
| **死循环** | 单个进程跳不出某个循环（被管理者的问题，如程序员的bug）|

> 死循环的进程可以上处理机运行，只是无法像期待的那样推进

#### 什么时候会发生死锁
1. **对系统资源的竞争**
2. **进程推进顺序非法**
3. **信号量使用不当**（如 P、V 操作顺序颠倒）

---

### 二、死锁产生的四个必要条件

**缺一不可！**

| 条件 | 说明 |
|------|------|
| **互斥条件** | 资源只能一个进程使用 |
| **不剥夺条件** | 资源只能主动释放，不能强行夺走 |
| **请求和保持条件** | 已持有一个资源，又请求新资源，被阻塞时不释放已有资源 |
| **循环等待条件** | 存在进程资源的循环等待链 |

> ⚠️ 发生死锁时**一定有**循环等待，但循环等待**未必**死锁（必要不充分条件）
> 循环等待链中的每个进程已获得的资源同时被下一个进程所请求

---

### 三、死锁的处理策略

```
预防死锁 ──→ 破坏四个必要条件之一（静态）
避免死锁 ──→ 银行家算法（动态，防止进入不安全状态）
检测死锁 ──→ 资源分配图化简
解除死锁 ──→ 资源剥夺 / 撤销进程 / 进程回退
```

---

### 四、预防死锁（静态）

| 破坏条件 | 方法 | 缺点 |
|---------|------|------|
| **互斥条件** | SPOOLing 技术把独占设备改造成共享设备 | 不是所有资源都能改造 |
| **不剥夺条件** | 请求失败→立即释放所有已有资源 / OS强行剥夺 | 实现复杂，可能**饥饿**，只适用于保存/恢复状态的资源 |
| **请求和保持条件** | **静态分配法**：运行前一次申请完所有资源，不满足不投入运行 | 资源利用率极低，可能**饥饿** |
| **循环等待条件** | **顺序资源分配法**：给资源编号，按编号递增顺序请求，同类一次申请完 | 编程麻烦，资源浪费，不方便增加新设备 |

---

### 五、避免死锁（动态）— 银行家算法

#### 核心思想
- 资源分配前预判是否会导致系统进入**不安全状态**
- **安全序列**：按此序列分配资源，每个进程都能顺利完成
- **安全状态**：能找出至少一个安全序列
- **安全状态 → 不会发生死锁**
- **不安全状态 → 可能发生死锁**（不是一定）

#### 数据结构
| 数据结构 | 说明 |
|---------|------|
| **Available** | 可用资源数 |
| **Max** | 各进程最大需求 |
| **Allocation** | 已分配资源 |
| **Need = Max - Allocation** | 还需要多少资源 |
| **Request** | 进程此次申请的资源数 |

#### 算法步骤
1. `Request ≤ Need`？→ 否则出错（超过最大需求）
2. `Request ≤ Available`？→ 否则等待（资源不足）
3. **试分配** → 修改 Available、Allocation、Need
4. **安全性检查**（找安全序列）
5. 安全 → **正式分配**；不安全 → 阻塞等待

---

### 六、死锁的检测和解除

#### 检测 — 资源分配图化简
- **资源分配图**：用图表示进程和资源之间的请求/分配关系
- 能消除所有边 → **无死锁**
- 不可简化 → **发生死锁**

#### 解除死锁
| 方法 | 说明 |
|------|------|
| **资源剥夺法** | 挂起某些死锁进程，剥夺其资源给其他进程 |
| **撤销进程法** | 强制撤销部分/全部死锁进程（代价小）|
| **进程回退法** | 让进程回退到足够避免死锁的状态（系统需记录历史状态）|
