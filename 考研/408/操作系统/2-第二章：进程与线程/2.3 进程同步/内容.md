## 2.3 进程同步 — 思维导图

### 一、基本概念

#### 进程同步
- **同步（直接制约关系）**：多个进程协调工作次序
- 原因：进程具有**异步性**（不可预知的速度推进）

#### 进程互斥
- **临界资源**：一个时间段只允许一个进程使用的资源
- **互斥**：一个进程访问临界资源时，其他必须等待

#### 访问临界资源的四个区
```
while (true) {
    进入区    // 检查是否可进入，上锁
    临界区    // 访问临界资源
    退出区    // 解锁
    剩余区    // 其他处理
}
```

#### 互斥的四个原则
| 原则 | 说明 |
|------|------|
| **空闲让进** | 临界区空闲时，允许一个进程进入 |
| **忙则等待** | 已有进程进入时，其他必须等待 |
| **有限等待** | 保证能在有限时间内进入 |
| **让权等待** | 不能进入时释放处理机，防止忙等 |

### 二、互斥的实现方法

#### 软件实现

| 方法 | 核心 | 问题 |
|------|------|------|
| **单标志法** | 轮流使用，权限由对方赋予 | 违背"空闲让进" |
| **双标志先检查** | 先检查后上锁 | 分析和上锁非原子 → 违背"忙则等待" |
| **双标志后检查** | 先上锁后检查 | 可能死锁 → 违背"空闲让进" |
| **Peterson算法** | 表达意愿 + 谦让 | 违背"让权等待"（仍忙等）|

#### 硬件实现

| 方法 | 说明 |
|------|------|
| **中断屏蔽** | 关中断，简单但不适于多核 |
| **TSL指令** | 原子操作，Check & Set |
| **Swap（XCHG）** | 原子交换，效果同TSL |
| **互斥锁（自旋锁）** | 忙等，适合多核、短上锁场景 |

### 三、信号量机制

#### 整型信号量
- 存在**忙等**问题（不满足让权等待）

#### 记录型信号量 ✅
```
typedef struct {
    int value;           // 剩余资源数
    struct process *L;   // 等待队列
} semaphore;

wait(S): S.value--; if <0 → block（自我阻塞）
signal(S): S.value++; if ≤0 → wakeup（唤醒等待进程）
```
- 遵循**让权等待**原则

#### 信号量的应用

##### 1. 实现互斥
```
P(mutex) → 临界区 → V(mutex)
```
- 互斥信号量 mutex 初值=1
- P、V 必须成对出现

##### 2. 实现同步
```
前操作 → V(S)    …    P(S) → 后操作
```
- 同步信号量 S 初值=0
- 口诀：**前 V 后 P**

##### 3. 实现前驱关系
- 每对前驱关系设置一个同步信号量
- 前操作后 V，后操作前 P

### 四、经典同步问题

#### 生产者-消费者
- empty（空缓冲区）、full（产品数）、mutex（互斥）
- ⚠️ 实现互斥的 P 操作要在实现同步的 P 操作**之后**

#### 多生产者-多消费者
- 爸爸放苹果、妈妈放橘子、儿子吃橘子、女儿吃苹果
- 缓冲区大小为1时，可能无需mutex

#### 读者-写者
- 多个读者可同时读，写者独占
- 读写公平法（FCFS）

#### 哲学家进餐
- 预防死锁的三种思路：
  1. 最多允许4人同时进餐
  2. 奇偶号哲学家拿筷顺序不同
  3. 仅当两根筷子都可用时才拿起

#### 吸烟者问题
- 单生产者-多消费者，用finish信号量实现轮流

### 五、管程

- **管程** = 共享数据结构 + 操作过程 + 初始化语句
- 每次仅允许一个进程在管程内执行
- 编译器负责实现互斥特性
- 条件变量 + wait/signal 解决同步问题
