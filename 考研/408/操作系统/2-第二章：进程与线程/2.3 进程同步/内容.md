## 2.3 进程同步 — 思维导图

### 一、基本概念

#### 进程同步（直接制约关系）
- 多个并发执行的进程以各自独立的、不可预知的速度向前推进（异步性）
- 需要在某些位置上协调他们的工作次序 → **同步**
- 如管道通信：写数据 → 读数据的顺序执行，不可颠倒

#### 进程互斥（间接制约关系）
- **临界资源**：一个时间段内只允许一个进程使用的资源
- **互斥**：当一个进程访问临界资源时，另一个想去访问的进程必须等待

#### 访问临界资源的四个区
```
while (true) {
    进入区    // 检查是否可进入，上锁
    临界区    // 访问临界资源（也称临界段）
    退出区    // 解锁
    剩余区    // 其他处理
}
```

#### 互斥的四个原则
| 原则 | 说明 |
|------|------|
| **空闲让进** | 临界区空闲时，允许一个进程立即进入 |
| **忙则等待** | 已有进程进入时，其他必须等待 |
| **有限等待** | 保证能在有限时间内进入临界区 |
| **让权等待** | 不能进入时立即释放处理机，防止忙等 |

---

### 二、互斥的实现方法

#### 软件实现

| 方法 | 核心思想 | 问题 |
|------|---------|------|
| **单标志法** | 每个进程用完转交权限给另一个 | 违背**空闲让进**（P0不进入则P1也不能进）|
| **双标志先检查** | 先检查→再上锁 | 检查和上锁非原子→违背**忙则等待** |
| **双标志后检查** | 先上锁→再检查 | 可能互相谦让全阻塞→违背**空闲让进** |
| **Peterson算法** | 表达意愿 + 谦让（turn） | 遵循前三原则，但违背**让权等待**（仍忙等）|

#### 硬件实现

| 方法 | 说明 | 特点 |
|------|------|------|
| **中断屏蔽** | 关/开中断指令 | 简单高效，不适于多处理机 |
| **TestAndSet（TSL）** | 原子操作：检查+上锁一气呵成 | 适用多处理机，但忙等（违背让权等待）|
| **Swap（XCHG）** | 原子交换，效果同TSL | 适用多处理机，但忙等 |
| **互斥锁（自旋锁）** | 忙等，适合多核短上锁 | 不满足让权等待 |

> TSL/SWAP 用硬件实现，执行过程不允许被中断，只能一气呵成

### 三、信号量机制

**信号量** = 一个变量，表示系统中某种资源的数量
**原语**：wait(S) / signal(S)，简称为 **P(S)、V(S)**

#### 整型信号量
- 用一个整数型变量表示资源数量
- 与普通整数变量的区别：操作只有三种 — 初始化、P操作、V操作
- ❌ 存在**忙等**问题（不满足让权等待）

#### 记录型信号量 ✅
```
typedef struct {
    int value;              // 剩余资源数
    struct process *L;      // 等待队列
} semaphore;

wait(S): S.value--;  if (S.value < 0)  → block(自我阻塞)
signal(S): S.value++; if (S.value <= 0) → wakeup(唤醒等待进程)
```
- ✅ 遵循**让权等待**原则（资源不足时主动阻塞，不会忙等）
- S.value 初值表示某种资源的数目
- **P操作** = 申请一个资源（S.value-1），不够则自我阻塞
- **V操作** = 释放一个资源（S.value+1），有等待则唤醒

#### 信号量的应用

##### 1. 实现进程互斥
```
P(mutex) → 临界区 → V(mutex)
```
- 互斥信号量 mutex **初值 = 1**
- P、V **必须成对出现**
- 不同临界资源需要设置不同的互斥信号量

##### 2. 实现进程同步
```
前操作 → V(S)    …    P(S) → 后操作
```
- 同步信号量 S **初值 = 0**
- 口诀：**前 V 后 P**
- 保证一前一后执行的两个操作

##### 3. 实现前驱关系
- 每对前驱关系设置一个同步信号量
- 前操作后 V，后操作前 P

> ⚠️ 实现互斥的 P 操作一定要在实现同步的 P 操作**之后**（否则可能死锁）

### 四、经典同步问题

#### 1. 生产者-消费者
- 一组生产者 + 一组消费者，共享大小为 n 的缓冲区
- 信号量：`empty = n`（空缓冲区数）、`full = 0`（产品数）、`mutex = 1`（互斥）
- **同步关系**：缓冲区没满→生产者放；缓冲区不空→消费者取
- **互斥关系**：缓冲区是临界资源，必须互斥访问
- ⚠️ P(mutex) 必须在 P(empty/full) **之后**

#### 2. 多生产者-多消费者
- 爸爸放苹果、妈妈放橘子、儿子吃橘子、女儿吃苹果
- 从 **"事件"角度**分析：盘子变空事件 → 放入水果事件
- 当缓冲区（盘子）= 1 时，可不用设置互斥信号量
- 用一个同步信号量解决多对事件的前后关系

#### 3. 读者-写者
- 多个读者可同时读，写者必须独占
- **读者优先**：读者持续进入→写者可能**饥饿**
- **读写公平法**：FCFS 处理（按请求顺序）

#### 4. 哲学家进餐
- 只有互斥关系，每个进程需同时持有两个临界资源 → **死锁隐患**
- 预防死锁三种思路：
  1. 最多允许 **4个**哲学家同时进餐
  2. 奇偶号哲学家拿筷顺序不同（奇左先右，偶右先左）
  3. 仅当两根筷子都可用时才拿起（用互斥信号量保护取筷动作）

#### 5. 吸烟者问题
- 单生产者 — 多消费者模型
- 用 finish 信号量实现轮流

### 五、管程（封装思想）

#### 信号量机制的问题
- 编写程序困难、易出错

#### 管程的组成部分
1. **局部于管程的共享数据结构**说明
2. 对该数据结构操作的**一组过程（函数）**
3. 对共享数据设置**初始值的语句**
4. **管程名字**

#### 管程的基本特征
1. 管程内的数据只能被管程内的过程访问
2. 一个进程只能通过调用管程内的过程才能访问共享数据
3. **每次仅允许一个进程在管程内执行内部过程**（互斥由编译器负责实现，程序员不需要关心）
4. 条件变量 + wait/signal 解决同步问题
