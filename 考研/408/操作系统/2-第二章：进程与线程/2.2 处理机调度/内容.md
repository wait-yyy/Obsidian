## 2.2 处理机调度 — 思维导图

### 一、调度的基本概念

- **处理机调度**：从就绪队列中按照一定的算法选择一个进程并将处理机分配给它运行
- 进程数量往往多于处理机个数，不可能同时并行处理

### 二、调度的三个层次

```
高级调度（作业调度）        中级调度（内存调度）        低级调度（进程调度）
外存 → 内存（面向作业）     外存 ↔ 内存（面向进程）    内存 → CPU（面向进程）
频率：最低                  频率：中等                  频率：最高（几十毫秒）
无 → 创建态 → 就绪态        挂起态 ↔ 就绪态            就绪态 → 运行态
```

#### 高级调度（作业调度）
- 按照一定原则从外存后备队列中挑选作业，分配内存等资源，建立PCB
- 主要是**调入**的问题（调出必然是作业运行结束）
- 频率最低

#### 中级调度（内存调度）
- 引入虚拟存储技术后，可将暂时不能运行的进程调至外存等待
- 决定哪个处于**挂起状态**的进程重新调入内存
- 一个进程可能被多次调出、调入 → 频率比高级调度更高
- **挂起态**：进程映像调出到外存，PCB 常驻内存（OS 通过 PCB 监控进程）

#### 低级调度（进程调度）
- 从就绪队列中选取一个进程，将处理机分配给它
- 操作系统中最基本的一种调度，频率很高

#### 七状态模型
```
                    ┌──→ 就绪挂起 ←──→ 阻塞挂起
                    │      （在外存）    （在外存）
创建态 → 就绪态 → 运行态 → 终止态
            ↑       ↓
            └── 阻塞态（在内存）
```

> 挂起 vs 阻塞：阻塞在内存等事件，挂起在外存等事件

### 三、进程调度

#### 调度时机

**需要调度的情况**：
- **主动放弃**：进程终止、异常终止、主动请求阻塞
- **被动放弃**：时间片用完、有更紧急事件、更高优先级进程

**不能调度的情况**：
- 处理中断过程中
- 进程在内核程序**临界区**中（访问内核数据结构如就绪队列）
- 原子操作（原语）过程中

#### 调度方式
| 方式 | 说明 |
|------|------|
| **非剥夺（非抢占）** | 进程主动放弃处理机才切换，适合批处理系统 |
| **剥夺（抢占）** | 有更紧迫进程时强制暂停当前进程，适合分时/实时系统 |

#### 进程切换
- **狭义进程调度**：从就绪队列选中一个要运行的过程
- **进程切换**：一个进程让出处理机，另一个进程占用处理机
- 切换过程：①保存原进程数据 ②恢复新进程数据
- 切换是有代价的，过于频繁会降低系统效率

### 四、调度算法的评价指标

| 指标 | 公式 | 说明 |
|------|------|------|
| **CPU利用率** | 忙碌时间 / 总时间 | 越高越好 |
| **系统吞吐量** | 完成作业数 / 总时间 | 单位时间完成的作业 |
| **周转时间** | 完成时间 - 提交时间 | 越小越好，含等待+运行 |
| **带权周转时间** | 周转时间 / 实际运行时间 | ≥1，越接近1越好 |
| **等待时间** | 等待处理机的时间总和 | 越小越好，用户满意度低 |
| **响应时间** | 提交到首次响应的时间 | 越小越好 |

### 五、调度算法详解

#### 先来先服务（FCFS）
- 按作业/进程到达先后顺序服务
- ✅ 非抢占式，公平，算法简单
- ❌ 对长作业有利，对短作业不利
- ❌ 不会导致饥饿

#### 短作业优先（SJF / SPF）
- 选择要求服务时间**最短**的作业/进程
- ✅ 非抢占式（也有抢占式版本 → **SRTN** 最短剩余时间优先）
- ✅ **平均等待时间、平均周转时间最短**
- ❌ 对长作业不利，可能产生**饥饿**（源源不断的短进程到来）

#### 高响应比优先（HRRN）
- **响应比 R = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + W/T**
- 综合考虑等待时间和要求服务时间
- ✅ 非抢占式
- ✅ 克服了SJF的缺点：长作业等待越久，响应比越大，不会饥饿
- ❌ 每次调度前要计算响应比，系统开销增加

> **三者对比**：等待时间相同时→短的优先（SJF优点）；服务时间相同时→等待久的优先（FCFS优点）

#### 时间片轮转（RR）
- 轮流让各进程执行一个**时间片**，未完成则重新放回就绪队列队尾
- ✅ 抢占式（时钟装置发中断通知时间片到）
- ✅ 公平、响应快，适用于分时操作系统
- ❌ 高频切换增加开销；不区分任务紧急程度
- ❌ 不会导致饥饿

**时间片大小选择**：
| 太大 | 太小 |
|------|------|
| 退化为FCFS | 进程切换过于频繁 |
| 增大响应时间 | 实际执行时间比例减小 |

#### 优先级调度
- 选择优先级最高的作业/进程
- 抢占式和非抢占式都有
- **优先级的设定**：
  - 系统进程 > 用户进程
  - 前台进程 > 后台进程
  - OS 更偏好 **I/O 型进程**
  - 动态优先级：等待时间长→提高优先级（追求公平/提高资源利用率）
- ✅ 区分紧急程度，适用于实时系统
- ❌ 源源不断高优先级进程到来→**饥饿**

#### 多级反馈队列调度
- 设置**多级就绪队列**，优先级从高到低，时间片从小到大
- 新进程先进入最高优先级队列
- 时间片内没完成→降级到下一级队列
- ✅ 综合多种算法优点：FCFS（公平）+ RR（响应快）+ SPF（短进程快）
- ✅ 不必事先估计进程运行时间
- ❌ 源源不断短进程到来→长进程**饥饿**

#### 算法适用场景
| 场景 | 适用算法 |
|------|---------|
| 批处理系统 | FCFS、SJF、HRRN |
| 交互式系统 | RR、优先级、多级反馈队列 |
