## 第一章：操作系统概述 — 思维导图

### 一、操作系统的概念

- **OS** = 控制和管理计算机 **硬件和软件** 资源
  - 合理地组织调度计算机的工作和资源分配
  - 提供给用户和其他软件方便的**接口和环境**
  - 计算机系统中最基本的**系统软件**
- 三个要点
  - 管理协调硬件、软件等资源
  - 为上层用户、应用程序提供服务
  - 是一种系统软件

---

### 二、操作系统的功能和目标

> 口诀：**处存备用**（处理机、存储、设备、文件、用户接口）

#### 1. 作为资源管理者
- **处理机（CPU）管理** — 进程管理
- **存储器管理** — 数据存放
- **文件管理** — 文件组织
- **设备管理** — I/O 设备

#### 2. 向上层提供服务

| 接口类型 | 子类 | 特点 |
|---------|------|------|
| 命令接口 | 联机（交互式） | 说一句做一句，如终端 |
| 命令接口 | 脱机（批处理） | 说一堆做一堆，如 .bat |
| 程序接口 | 系统调用 | 程序中调用，如函数调用 |

- GUI 和命令接口：用户**直接**使用
- 程序接口：通过程序**间接**使用

#### 3. 对硬件的拓展
- **裸机** → OS 包装 → **扩充机器（虚拟机）**

---

### 三、操作系统的四个特征

> **并发**和**共享**是最基本的特征，**互为存在条件**

```
    并发性 ←→ 共享性（最基本，互为条件）
       ↓             ↓
     虚拟性 ←──── 异步性
（没有并发/共享，就没有虚拟/异步）
```

#### 1. 并发性
- **并发**：宏观同时，微观交替
- **并行**：同一时刻同时发生
- ⚠️ 单核CPU只能**并发**，多核CPU才能**并行**
- 多核CPU运行程序数 > 核数时，仍需并发
- OS 伴随"多道程序技术"诞生

#### 2. 共享性
- **互斥共享**：一段时间内只允许一个进程访问
- **同时共享**：宏观上多个进程"同时"访问（微观交替）

#### 3. 虚拟性
- 物理实体 → 逻辑对应物
  - **空分复用**：虚拟存储器（4GB 内存看似更大）
  - **时分复用**：虚拟处理器（单核看似多核）

#### 4. 异步性
- 进程以不可预知的速度推进（走走停停）
- 只有系统拥有并发性才可能导致异步性

---

### 四、OS 的发展与分类

```
手工操作阶段 ──→ 单道批处理系统 ──→ 多道批处理系统 ──→ 分时操作系统 ──→ 实时操作系统
（人机矛盾）      （脱机I/O）        （并发、共享）      （时间片轮转）    （及时、可靠）
```

#### 手工操作阶段
- 缺点：用户独占全机、人机速度矛盾

#### 单道批处理系统
- 脱机输入/输出技术，监督程序控制
- 缓解人机矛盾，但CPU仍大量空闲

#### 多道批处理系统
- 多道程序**并发**执行，**共享**资源
- 优点：资源利用率大幅提升
- 缺点：无交互，响应时间长

#### 分时操作系统
- 时间片为单位轮流服务
- 优点：解决人机交互
- 缺点：不能优先处理紧急任务

#### 实时操作系统

| 类型 | 特点 | 案例 |
|------|------|------|
| 硬实时 | 必须严格时限内完成 | 导弹控制、自动驾驶 |
| 软实时 | 可接受偶尔违反 | 火车订票系统 |

#### 其他系统
- 网络 OS：资源共享、通信
- 分布式 OS：分布性、并行性
- 个人计算机 OS

---

### 五、操作系统的运行机制

#### 1. 两类程序
- **应用程序**：普通程序
- **内核程序**：组成 OS 内核，最接近硬件

#### 2. 两类指令
- **特权指令**：只允许内核使用
- **非特权指令**：应用程序可用（如加法指令）

#### 3. 两种处理器状态
- **内核态（管态）**：运行内核程序，可执行特权指令
- **用户态（目态）**：运行应用程序，只能执行非特权指令
- PSW（程序状态字寄存器）中 1=内核态，0=用户态

#### 4. 内核态和用户态的切换
- 内核态→用户态：修改 PSW（主动让出CPU）
- 用户态→内核态：**中断**引发（硬件自动完成）

---

### 六、中断和异常

#### 1. 中断的作用
- 让 OS 内核夺回 CPU 使用权的**唯一途径**
- 使 CPU 从用户态转为内核态

#### 2. 中断的类型

```
中断
├── 内中断（异常）：与当前指令有关，信号来源于CPU内部
│   ├── 陷入（trap）：主动，如系统调用
│   ├── 故障（fault）：可修复，修复后归还CPU
│   └── 终止（abort）：致命错误，不归还CPU
└── 外中断（狭义中断）：与当前指令无关，来源于CPU外部
    ├── 时钟中断：实现多道程序并发
    └── I/O中断：I/O 任务完成时
```

#### 3. 中断机制基本原理
- 不同中断 → 不同中断处理程序
- CPU 查询 **中断向量表** 找到处理程序
- 中断处理程序运行在内核态

---

### 七、系统调用

#### 1. 概念
- OS 提供给应用程序的接口
- 应用程序通过系统调用请求 OS 内核服务

#### 2. 作用
- **凡是与共享资源有关的操作，都必须通过系统调用**
  - 存储分配、I/O操作、文件管理
- 保证系统的**稳定性**和**安全性**

#### 3. 系统调用 vs 库函数
```
应用程序
  ↑       ↑
库函数 (封装系统调用或不涉及系统调用)
  ↑
系统调用
  ↑
操作系统
```

#### 4. 系统调用分类
- 设备管理、文件管理、进程管理、进程通信、内存管理

#### 5. 系统调用过程
```
用户态：应用程序 → 库函数（传参）→ 执行陷入指令
    ↓（引发中断）
核心态：内核处理中断 → 执行系统调用 → 返回应用程序
```

- ⚠️ 陷入指令在**用户态**执行，对系统调用的处理在**核心态**

---

### 八、操作系统体系结构

#### 大内核（宏内核）
- 主要功能模块都作为内核，运行在核心层
- 优点：高性能  |  缺点：代码庞大、难维护
- 代表：Linux、UNIX

#### 微内核
- 只保留最基本功能（中断、原语、进程通信）
- 优点：内核小、易维护、可靠性高
- 缺点：需频繁切换核心态/用户态，性能低
- 代表：Windows NT

#### 其他结构
- **分层结构**：每层只能调用更低一层
- **模块化**：按功能划分为模块，模块间通过接口通信
- **外核**：内核负责调度/通信，外核分配未经抽象的硬件资源

---

### 九、OS 引导（Boot）

```
CPU读ROM引导程序 → 硬件自检
  → 读磁盘MBR（主引导记录），扫描分区表
  → 从活动分区读PBR（分区引导记录）
  → 从根目录找到启动管理器 → 完成开机
```

### 十、虚拟机

- **第一类 VMM**：直接运行在硬件上（性能好，支持更多VM）
- **第二类 VMM**：运行在 Host OS 上（迁移性好，性能差）
