## 第四章：文件管理 — 思维导图

### 一、文件系统基础

#### 文件属性
- 文件名、标识符、类型、位置、大小
- 创建/修改时间、所有者、保护信息

#### 文件的逻辑结构
| 类型 | 说明 |
|------|------|
| **无结构文件（流式文件）** | 二进制/字符流，如 .txt |
| **有结构文件（记录式文件）** | 由记录组成 |
| └─ 顺序文件 | 记录顺序排列 |
| └─ 索引文件 | 建索引表实现快速查找 |
| └─ 索引顺序文件 | 分组+索引，可多级索引 |

#### 文件目录
- **FCB（文件控制块）** = 目录项
- 目录是一种特殊的有结构文件，目录 = 文件夹
- **目录结构演进**：
  ```
  单级 → 两级(MFD+UFD) → 树形(路径) → 无环图(共享)
  ```
- **inode（索引结点）**：文件名与信息分离 → 缩小目录项

#### 文件的物理结构（分配方式）

类似于内存分页，磁盘块大小常与内存块、页面大小相同

| 方式 | 特点 |
|------|------|
| **连续分配** | 支持顺序访问和**直接访问**（物理块号 = 起始块号 + 逻辑块号），有碎片，不方便扩展 |
| **隐式链接** | 目录记录起始块号和结束块号，盘块存指向下一个盘块的指针，只支持**顺序访问** |
| **显式链接（FAT）** | **文件分配表** FAT 常驻内存，目录记录起始块号，支持**随机访问** |
| **索引分配** | 每文件一张索引表（链接方案/多层索引/混合索引）|

**连续分配**：
- 顺序读/写速度最快（磁盘指针）
- 拓展不方便
- 有磁盘碎片（类似外部碎片），可用紧凑解决但代价大

**隐式链接**：
- 指针对于用户透明
- ✅ 方便文件拓展，无碎片问题，外存利用率高
- ❌ 只支持顺序访问，不支持随机访问

**显式链接（FAT）**：
- FAT 把各物理块的指针显式存放
- 逻辑块号 → 物理块号不需要读磁盘操作
- ✅ 支持顺序和随机访问，速度很快

**索引分配**：
- 索引表存放的块 = **索引块**，文件数据存放的块 = **数据块**
- ✅ 支持随机访问，方便拓展

**索引表太大时的解决方案**：

| 方案 | 说明 |
|------|------|
| **链接方案** | 多个索引块链接存放，但访问大文件需顺序读入多个索引块→低效 |
| **多层索引** | 类似多级页表，即使小文件也需 k+1 次读磁盘 |
| **混合索引** | 直接地址 + 一级间接 + 二级间接 → 小文件读磁盘次数少，综合最优 |

> 混合索引：一个顶级索引表中既含直接地址索引（指向数据块），又含一级间接索引（指向单层索引表），还含两级间接索引

### 二、存储空间管理

| 方法 | 说明 |
|------|------|
| **空闲表法** | 记录连续空闲区（适用连续分配，首次/最佳/最坏适应）|
| **空闲链表法** | 空闲盘块链（适用离散分配）/ 空闲盘区链（适用连续+离散）|
| **位示图法** | 二进制位表示盘块状态 |
| **成组链接法** | UNIX 使用，**超级块**管理分组 |

**空闲链表法**：
- **空闲盘块链**：OS 保存链头链尾指针，分配摘链头，回收挂链尾
- **空闲盘区链**：可连续也可离散分配，效率更高，回收注意合并相邻空闲区

**位示图法**：
- 分配：扫描找 K 个 "0" → 算盘块号 → 分配 → 置 "1"
- 回收：盘块号算字号位号 → 置 "0"

**成组链接法**（UNIX）：
- 文件卷的目录区用一个磁盘块作为 **超级块**（链头作用）
- 系统启动时超级块读入内存
- 需保证内存与外存的超级块数据一致

### 三、文件的基本操作

#### 创建文件（create 系统调用）
**需要参数**：外存空间大小、文件存放路径、文件名
**OS处理**：
1. 在外存中找到文件所需的空间（空闲链表法/位示图/成组链接法）
2. 在目录中创建该文件对应的目录项（FCB）

#### 删除文件（delete 系统调用）
**OS处理**：
1. 找到目录项，回收文件占用的磁盘块
2. 从目录表中删除文件对应的目录项

#### 打开文件（open 系统调用）
**需要参数**：文件存放路径、文件名、操作类型
**OS处理**：
1. 找目录 → 找目录项 → 检查用户权限
2. 将目录项复制到内存中的 **打开文件表** 中
3. 返回对应表目的编号（文件描述符 fd）
4. 之后用户用 fd 指明要操作的文件

#### 读文件（read 系统调用）
- 从读指针指向的外存中，将用户指定大小的数据读入内存指定区域

#### 写文件（write 系统调用）
- 从用户指定的内存区域中，将指定大小的数据写回写指针指向的外存

#### 关闭文件（close 系统调用）

### 六、文件系统

#### 层次结构（从上到下）
```
用户接口（处理系统调用 Read/Write/Open/Close）
    ↓
文件目录系统（按路径找 FCB/inode，管理目录）
    ↓
存取控制模块（验证用户访问权限）
    ↓
逻辑文件系统与文件信息缓冲区（记录号 → 逻辑地址）
    ↓
物理文件系统（逻辑地址 → 物理地址）
    ↓
辅助分配模块（分配/回收存储空间）
    ↓
设备管理模块（分配设备、缓冲区、磁盘调度、启动设备）
    ↓
设备
```

#### 外存布局
```
原始磁盘 → 物理格式化（划分扇区、检测坏扇区）
  → 磁盘分区（分卷 Volume）
  → 逻辑格式化（文件系统初始化）
```

**逻辑格式化后的结构**：
```
| MBR | 引导块 | 超级块 | inode区 | 根目录 | 文件区 |
```
- **MBR（主引导记录）**：包含磁盘引导程序和分区表
- **引导块**：存放自举程序
- **超级块**：文件系统元信息（空闲块数、inode数等）
- **inode 区**：存储所有文件的索引结点

#### 文件系统在内存中的结构
- **安装表** — 记录已挂载的文件系统
- **目录缓存** — 近期访问过的目录缓存在内存
- **系统打开文件表** — 每个打开文件一个表项（含打开计数器）
- **进程打开文件表** — 每个进程一张，指向系统打开文件表

#### Open 系统调用的完整过程
1. 用户进程调用 open → 系统调用 → VFS
2. 根据文件路径逐层查找目录 → 找到 FCB/inode
3. 检查权限
4. 在系统打开文件表中分配表项（若已打开则计数器+1）
5. 在进程打开文件表中增加表项，指向系统打开文件表
6. 返回文件描述符 fd

#### 虚拟文件系统（VFS）
- **向上**：提供统一标准的系统调用接口，屏蔽底层差异
- **向下**：要求下层文件系统必须实现规定的函数（open/read/write）
- 每打开一个文件 → 在内存中创建 **vnode**（统一的数据结构）
- 不同文件系统的 vnode 指向各自的具体文件结构
