## 第五章：设备管理 — 思维导图

### 一、I/O 硬件

#### I/O 设备组成
- **机械部件** — 设备本身
- **电子部件** — **设备控制器**（适配器）

#### 设备控制器功能（含寄存器）
1. 接收和识别 CPU 命令（**控制寄存器 CR**）
2. 数据交换（**数据寄存器 DR**）
3. 标识和报告设备状态（**状态寄存器**）
4. 地址识别（CPU 通过地址判断读写哪个寄存器）
5. 数据缓冲

> 一个 IO 控制器可能对应多个设备，各类寄存器可能有多个

#### 寄存器编址方式
| 方式 | 特点 |
|------|------|
| **内存映像 I/O** | 寄存器与内存统一编址，可用内存操作指令控制，指令更简化 |
| **寄存器独立编址** | 寄存器单独地址空间，需专门 I/O 指令，需指明寄存器地址和控制器编号 |

### 二、I/O 控制方式

```
程序直接控制 ──→ 中断驱动 ──→ DMA ──→ 通道控制
  （轮询）       （中断通知）   （块传输）  （通道程序）
```

| 方式 | CPU干预频率 | 数据单位 | 数据流向 | 特点 |
|------|-----------|---------|---------|------|
| **程序直接控制** | 频繁轮询 | 字 | 设备→CPU→内存 | 实现简单，CPU**忙等**，串行 |
| **中断驱动** | 每字中断 | 字 | 设备→CPU→内存 | CPU可并行，每字中断→开销大 |
| **DMA** | 开始+结束时 | **块** | 设备↔内存（直接）| 效率高，无需CPU中转 |
| **通道控制** | 极低（一组块完成）| **一组块** | 设备↔内存 | 用通道程序，并行度高 |

#### 程序直接控制方式（轮询）
1. CPU 发读指令 → IO 控制器启动设备，状态寄存器置 1
2. CPU 不断**轮询**状态寄存器（设备比 CPU 慢很多）
3. 设备准备好数据 → 传给 IO 控制器 → 状态寄存器改 0
4. CPU 发现状态为 0 → 从数据寄存器读入 CPU 寄存器 → 再放入内存
- ❌ CPU 和设备**串行工作**，CPU 利用率极低

#### 中断驱动方式
- CPU 发读写指令后 → 可将等待 IO 的进程**阻塞** → 切换到别的进程执行
- IO 完成后 → 设备发出**中断信号** → CPU 处理中断 → 将数据从 IO 控制器传至内存
- ✅ CPU 与 IO 设备可**并行工作**
- ❌ 每次传输一个字，大量中断消耗 CPU 时间

#### DMA 方式
**DMA 控制器寄存器结构**：
| 寄存器 | 作用 |
|--------|------|
| **DR（数据寄存器）** | 暂存从设备到内存或从内存到设备的数据 |
| **MAR（内存地址寄存器）** | 数据在内存中的位置 |
| **DC（数据计数器）** | 剩余要读/写的字节数 |
| **CR（命令/状态寄存器）** | 存放 CPU 发来的 IO 命令或设备状态 |

**特点**：
- 数据传输单位是**块**，不是字
- 数据流向：**设备 ↔ 内存直接**，无需通过 CPU
- 仅在传送开始和结束时需要 CPU 干预
- ✅ 效率高
- ❌ 每次只能读写**连续的**多个块，读入内存也必须是连续的

#### 通道控制方式
- **通道** = 弱化版 CPU（硬件），执行**通道程序**
- CPU 干预率极低：仅在一组数据块读写完成后发中断
- 三者（CPU、通道、设备）并行度最高，实现最复杂

### 三、I/O 软件层次结构

```
用户层软件          ← 假脱机技术（SPOOLing）
设备独立性软件      ← I/O调度、设备保护、设备分配、缓冲区管理、LUT映射
设备驱动程序        ← 与硬件相关，每类设备一个驱动
中断处理程序        ← 处理中断信号
硬件                ← 设备
```

#### 各层功能
- **用户层软件**：实现 SPOOLing 技术，请求磁盘设备的服务
- **设备独立性软件**：
  - I/O 调度、设备保护、设备分配与回收、缓冲区管理
  - **差错处理**
  - 建立 **逻辑设备名 → 物理设备名** 的映射（通过 **LUT** 逻辑设备表）
  - LUT 设置：单用户→系统一张；多用户→每用户一张
- **设备驱动程序**：每类设备对应一个驱动，负责与硬件交互（不同硬件特性需要不同驱动）
- **中断处理程序**：收到中断信号 → 找到对应的中断处理程序执行

### 四、SPOOLing 技术（假脱机）

#### 原理
```
输入设备 → 输入缓冲区 → 输入进程 → 输入井（磁盘）
                                        ↓
                                    用户进程
                                        ↓
输出设备 ← 输出缓冲区 ← 输出进程 ← 输出井（磁盘）
```
- 用**软件的方式**模拟脱机技术
- 将独占设备改造为**共享设备**（虚拟设备）

#### 共享打印机实例
1. 用户进程在磁盘**输出井**中申请空闲缓冲区，将要打印的数据送入
2. 为用户进程申请一张空白的**打印请求表**（说明数据位置等信息），挂到假脱机文件队列
3. 打印机空闲时，输出进程从队列取出打印请求表，从输出井取数据 → 打印

### 五、设备分配

#### 设备固有属性
| 类型 | 说明 |
|------|------|
| **独占设备** | 一个时段只能一个进程使用 |
| **共享设备** | 可同时多个进程使用（如磁盘）|
| **虚拟设备** | SPOOLing 技术将独占改造成共享 |

#### 四级数据结构
```
系统设备表(SDT) → 设备控制表(DCT) → 控制器控制表(COCT) → 通道控制表(CHCT)
```

#### 分配步骤
1. 查 **SDT**（系统设备表）→ 找 **DCT**（设备控制表）
2. 设备空闲？→ 分配 → 查 **COCT**（控制器控制表）
3. 控制器空闲？→ 分配 → 查 **CHCT**（通道控制表）
4. 通道空闲？→ 分配成功，启动 I/O

> **只有设备、控制器、通道三者都分配成功，才算分配成功**

#### 分配方式
- **安全分配方式**：分配设备后进程阻塞，IO 完成后唤醒（不产生死锁）
- **不安全分配方式**：进程可继续发出新 IO 请求，仅请求不满足时才阻塞（可能死锁）
- **静态分配**：运行前分配全部资源，运行结束后归还
- **动态分配**：运行过程中动态申请

#### 分配改进 — LUT（逻辑设备表）
- **问题**：用户编程用物理设备名 → 不透明、不灵活；设备忙→即使有同类设备也必须等待
- **改进**：用户用**逻辑设备名**编程
- OS 通过 **LUT** 建立逻辑名 ↔ 物理名映射

### 六、缓冲区管理

#### 缓冲区作用
- 缓和 CPU 与 I/O 速度不匹配
- 减少中断频率
- 解决数据粒度不匹配
- 提高 CPU 与 I/O 并行性

#### 缓冲策略（T=输入时间，C=处理时间，M=传送时间）
| 类型 | 说明 | 处理一块数据耗时 |
|------|------|----------------|
| **单缓冲** | 一个缓冲区，数据非空时不能冲入，为空时需充满才能传出 | **Max(C, T) + M** |
| **双缓冲** | 两个缓冲区，可交替使用 | **Max(T, C+M)** |
| **循环缓冲** | 多个缓冲区循环队列（in/out指针）| — |
| **缓冲池** | 系统共用（空/输入/输出队列 + hin/sin/hout/sout）| — |

> 口诀：单缓冲 = 大者 + M；双缓冲 = 取大者

**双缓冲用于通信**：
- 两个机器通信时只设单缓冲区→任意时刻只能单向传输
- 要实现双向传输必须设置**两个管道**（管道本身也是缓冲区）
- 循环缓冲区可缓解此问题

### 七、磁盘结构

#### 磁盘、磁道、扇区
- **柱面（Cylinder）**、**磁头（Head）**、**扇区（Sector）**
- 定位一个磁盘块：(柱面号，盘面号，扇区号)
- 所有磁头连在同一个磁臂上 → 所有磁头只能 **"共进退"**
- 寻道操作：① 按柱面号移动磁臂 → ② 激活对应磁头 → ③ 旋转使扇区划过磁头

#### 一次磁盘读/写操作需要的时间
| 时间 | 说明 |
|------|------|
| **寻道时间** | 磁头移动到指定磁道（启动磁臂 + 移动磁头）|
| **延迟时间** | 旋转磁盘使磁头定位到目标扇区 |
| **传输时间** | 从磁盘读出或写入数据 |

### 八、磁盘调度算法 ★

| 算法 | 核心 | 特点 |
|------|------|------|
| **FCFS** | 按请求顺序调度 | 公平，但性能差 |
| **SSTF（最短寻道优先）** | 优先处理最近的请求 | 性能好，但可能**饥饿**（贪心算法）|
| **SCAN（电梯算法）** | 单向移动，到头折返 | 解决饥饿，但各位置响应频率不平均 |
| **C-SCAN** | 单向移动，直接回起点 | 各位置等待时间更均匀 |
| **LOOK** | SCAN 改进，无请求即可折返 | 不需要每次都移动到最外侧/最内侧 |
| **C-LOOK** | C-SCAN 改进 | 综合最优 |

> LOOK 和 C-LOOK 是 SCAN 和 C-SCAN 的改进版，避免不必要的寻道到端点

#### 减少延迟时间的方法
- **扇区交替编号**：逻辑相邻扇区物理上隔开，给磁头处理数据留时间
- **柱面扇区错位**：不同盘面错开扇区起始（所有盘面一起连轴转）

### 九、磁盘管理

#### 磁盘初始化步骤
1. **低级格式化（物理格式化）**：将各磁道划分为扇区（头+数据+尾，含校验码）
2. **磁盘分区**：每个分区由若干柱面组成（C盘、D盘等）
3. **逻辑格式化**：创建文件系统 → 根目录、位示图、空闲分区表

#### 磁盘引导
- **ROM** 中存放很小的"自举装入程序"
- 开机时运行自举装入程序 → 找到磁盘**引导块** → 将完整自举程序读入内存 → 完成初始化
- 拥有启动分区的磁盘称为**启动磁盘**或**系统磁盘**

#### 坏块管理
- 逻辑格式化时对整个磁盘进行坏块检查
- 在 FAT 中标记坏扇区（简单磁盘）
- 复杂磁盘：控制器维护坏块链表，保留**备用扇区**替换坏块（对 OS 透明）
